# RA v1.6.0 Safety Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** RA records the agent that really ran, refuses other agents without a user grant, routes every delete through one checked and recoverable door, and asks templated questions at key moments.

**Architecture:** The logic lives in `scripts/ra_common.py` (identity, templates, answers check, permissions, delete-path classifier), so every harness gets it through the RA scripts. `ra_gate.py` and `ra_context_harness.py` add the commands and refusals. `ra_hooks.py` adds a shell classifier for Claude Code. `ra_forge.py` writes OpenCode permission rules for OpenCode.

**Tech Stack:** Python 3.12 stdlib only (scripts run as `python -I`), pytest 9 for tests, Claude Code hooks, OpenCode 2.2.7 permission rules.

**Spec:** `docs/design/2026-11-11-safety-harness-design.md` (read it first, it holds the why and Kano's words).

## Global Constraints

- Edit only the source repo `C:\Users\me\.gemini\skills\research-anything`. Never edit `skills/research-anything/` (the installer's mirror) or the installed copies under `~/.claude`, `~/.agents`, `~/.config/opencode`, `~/.codex`, `~/.gemini/config`.
- No commits, no pushes. Kano commits. Leave changes in the working tree.
- Python stdlib only, no new dependencies. Scripts must keep running as `python -I <script>`. Note that `-I` ignores `PYTHONIOENCODING`.
- Output must survive a cp932 console: write via `sys.stdout.buffer` / `sys.stderr.buffer` in UTF-8, as the existing scripts do, or keep it ASCII.
- Hooks fail open on internal errors (exit 0), as `ra_hooks.py:606-611` does today. A deliberate safety block exits 2.
- Identity format: `opencode:<providerID>/<modelID>`, `claude-code:<model>`, `codex:<model>`, `agy:<model>`, with `unknown` for any part that can't be read. Never substitute the `--agent` value.
- Paths in SKILL.md use `"${CLAUDE_SKILL_DIR}/..."`, never `~`.
- Tests go in a new `tests/` at the repo root. The installer doesn't ship it, since `ROOT_SKILL_PARTS` is `SKILL.md, agents, scripts, references, resources`. Tests drive the scripts through `subprocess` with `python -I` in `tmp_path` workspaces made by `ra_gate.py init`.
- Comments: one short line per thing, and only where the reader can't see the why.

## Review Focus

1. **Everyday commands must not be blocked:** `git status`, `grep -rn rm src/`, `cat claude_notes.md`, `python claude_shim.py`, `echo "rm -rf is dangerous"`, `rm` inside a heredoc body, `npm uninstall x`. All must pass the classifier (test in Task 5).
2. **Windows path forms in deletes:** quoted paths with spaces (`"F:\My Project\research\sandbox\x"`), backslashes, `WAPAPA~1` short names, another drive letter, `..` escapes, junctions. These must classify by the real resolved path (tests in Task 4 for `remove`, and Task 5 for the hook).
3. **Identity source missing or locked** (no `opencode.db`, a locked DB, no session row yet, a transcript with no assistant message yet): this must give `<harness>:unknown`, never a crash, and never the claimed name (test in Task 2).
4. **Old projects:** `.ra_state.json` files from v1.5 and earlier records with `PRIMARY_AGENT` or wrong names. New records must be correct, old records untouched, no crash (test in Task 2).
5. **Hook time limit:** the Claude hook timeout is 10 s. The transcript read for the model must only read the tail (reuse `TAIL_CAP` / the tail-read approach in `ra_hooks.py`), and the classifier must not touch the network or spawn processes (test in Task 5: a 50 MB fake transcript resolves in under 1 s).
